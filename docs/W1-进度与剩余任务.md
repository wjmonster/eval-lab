## 零、先搞清楚：这两天到底在干什么（目的，不是步骤）

**一句话：把"AI 输出没法复现"这件事，变成"你能记录、能重复、能对比"。**

你以前做传统测试，测的是一个**确定函数**：输入 1+1，永远得 2，所以你敢写 `assert result == 2`。
AI 是一个**概率函数**：同一个问题问 10 次，10 个答案，措辞不同、长度不同、偶尔编造。所以：

- 不是"没法写断言"，而是**你得先把每次输出记下来**，否则"它这次答得不对"这句话没有证据、也复现不出来。
- 这恰好是测试工程师的本能——**缺陷单必须有复现步骤**。AI 测试的第一步，就是造出这份"复现记录"。

所以这两天不是"学写代码"，是搭三个东西：

| 搭什么 | 白话说 | 你原来的工作里对应什么 |
|---|---|---|
| 一个**开关** | 能随时换模型（换 provider） | 能在不同测试环境之间切 |
| 一个**记录仪** | 每次调用落一条：输入、输出、token、耗时、成本 | 缺陷单的复现记录 |
| 一个**对比台** | 同一问题扔给多家模型，并排看差异 | 兼容性测试 / 多环境对比 |

## 一、D1 的目标：让"能调通一个真模型并留下证据"

**D1 完成的标志**：`calls.jsonl` 里有 3 条 `provider` 是 `zhipu` 的记录，`output` 是真实回答（不是"这是 mock 回复"）。

## 二、D2 的目标：让"同一件事，能看出不同模型差在哪"

| 你要做的动作 | 目的（为什么） | 对应你原来的工作 |
|---|---|---|
| 为什么跑 **3 次**而不是 1 次 | AI 每次输出都不一样。跑 1 次你看到的是偶然，跑 3 次才能看出"它稳不稳" | 同一个用例跑多次，看是否稳定复现 |
| 为什么要**四家**一起跑 | 同一问题不同模型答案不同。四家并排，你才能说清"这个差别是模型造成的，还是我提示词造成的" | 兼容性测试：同一功能在不同环境表现不同 |
| 为什么加 `--temperature 0` | 验证一个流传很广的错误认知："温度设 0 就确定了"。实际不是 | 控制变量法：只改一个因子，看结果变不变 |

**D2 完成的标志**：屏幕上有一张表四家并排，并且你能写出一句自己的观察（例如"硅基流动延迟波动最大，deepseek 最稳"）。**那句观察才是产出，表只是素材。**

## 九、W1 过关自测（现在就能答，答不出说明 unit1 白读了）

1. **temperature=0，同一个 prompt 为什么还可能不一样？**
   提示：temperature 控制的是采样，不是"确定性"；浮点求和顺序、并行 batch、GPU kernel 都可能引入差异。
2. **上下文溢出时，被丢掉的是哪一部分？**
   提示：取决于你的截断策略和 chat template——通常是保留 system + 最近若干轮，中间被裁。所以"长会话后期答得差"往往不是模型变笨，是你的历史被裁了。
3. **429 重试为什么要加随机抖动（jitter）？**
   提示：所有客户端按固定间隔同步重试，会在同一秒形成重试风暴，把限流打得更死。

> 这三问对应 unit1 第 2、10 节。答不出来就回去看那两节的批注。
