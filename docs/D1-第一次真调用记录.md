## 二、三个观察（都是这批数据里长出来的，不是我编的）

### 1）温度设 0，三次输出逐字相同

所以"温度 0 = 完全确定"这个说法，**在小模型短回答上看着是成立的**。但别急着下结论：换成长回答、换更大的模型、换不同机器，同样的温度照样会飘。要证明"确定"，得跑 10 次以上，且换几种输入长度再验。

### 2）延迟第一次 2430 ms，后两次 1078 / 1107 ms——差 2.2 倍

同一 prompt、同一模型、同一温度，只因为"第一次"。可能原因：连接建立、模型冷启动、服务端排队。
**结论**：延迟指标必须多次取中位数，**单次测出来的延迟基本没有意义**。这条直接对应你后面要给 Agent 定超时阈值——按单次最大值设超时，会把正常请求全部杀掉。

### 3）★ 真正的 bug：三次都把"幻觉"答成了**医学**的幻觉

模型给的定义是"大脑在没有外部刺激时产生的虚假感觉或知觉"——这是精神科的幻觉。
而你的语境是**大模型的幻觉（hallucination）**：模型编造不存在的事实、伪造引用、答得理直气壮但事实错误。

这个答案：语法正确、格式正确、有头有尾、不违反任何规则。**所有传统断言都会 PASS。**

## 三、为什么这一条对你特别重要

把这次输出拆开看，正好演示了"确定性断言能抓什么、抓不到什么"：

| 检查项 | 这次能抓到吗 |
|---|---|
| 有没有返回（非空） | 能，PASS |
| finish_reason 是否 stop | 能，PASS |
| token 数是否在预算内 | 能，PASS |
| 有没有超时 / 429 | 能，PASS |
| **答的内容对不对题** | **抓不到** —— 它答的是另一个领域的"幻觉" |

也就是说：**格式层全绿，语义层是错的。** 这类失败就是 AI 测试和传统测试的分水岭：

- 传统测试里，"答错"通常等于"功能错了"，一个断言就能锁定；
- 这里，"答得通顺但答错领域"只能靠**评分规则（rubric）或 LLM 当裁判**来判，而且裁判本身也可能错，所以要校准。

这也是你 W3 要写 `scorers/deterministic.py` 和 `scorers/llm_judge.py` 两层的真实原因——不是"多写点代码显得专业"，是**上面那张表里最后一行，第一种方法永远抓不到**。
