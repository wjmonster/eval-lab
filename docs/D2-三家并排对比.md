# D2 三家并排对比 + 一次归因

**日期**：2026-11-18　**温度**：0.0　**prompt**：`用一句话解释什么是幻觉`
**命令**：`uv run eval-lab compare --prompt "用一句话解释什么是幻觉" --providers zhipu,siliconflow,qwen --repeat 3`

## 一、并排表（每家 3 次）

| provider | model | 次数 | 最小延迟 | **中位延迟** | 最大延迟 | 输入 tok | 输出 tok | 成本/次 | 失败 |
|---|---|---|---|---|---|---|---|---|---|
| siliconflow | `Qwen/Qwen2.5-7B-Instruct` | 3 | 344 ms | **551 ms** | 3088 ms | 35 | 14 | 0 | 0 |
| zhipu | `glm-4-flash` | 3 | 1327 ms | **1519 ms** | 2559 ms | 10 | 17 | 0 | 0 |
| qwen | `qwen-plus` | 3 | 1836 ms | **2231 ms** | 2841 ms | 14 | 60 | 0.0001 | 0 |

> 另有前序单独验证跑：siliconflow 2 次（4374 / 516 ms）、zhipu 3 次（2430 / 1078 / 1107 ms）、qwen 2 次（2841 / 2753 ms）、zhipu 改 prompt 1 次。全部落库在 `results/calls.jsonl`，现共 30 条（mock 13 + 真模型 17）。

## 二、观察 A：延迟不是"一个数"，是一个区间

- siliconflow：**344 → 3088 ms**，最大是最小的 **9 倍**
- 前面单独测时它出现过 **4374 ms 和 516 ms**，差 8.5 倍
- zhipu：1078 → 2559，差 2.4 倍
- qwen：1836 → 2841，差 1.5 倍，是三家最稳的

**所以**：只跑 1 次得出的延迟，**不能写进任何结论**，也不能拿来定超时阈值。至少要 3 次取中位数；要定超时，得看 p95，别拿最小值当常态。

## 三、观察 B：token 计数口径各家不同

同一句 8 个字的 prompt，同一句意思的回答：

| provider | 输入 tok | 输出 tok |
|---|---|---|
| zhipu | 10 | 17 |
| siliconflow | 35 | 14 |
| qwen | 14 | 60 |

同一句话，输入 token 差 3.5 倍。原因：各家底层 tokenizer 不同，还有的会把 system/模板 token 算进去。
**所以**：跨家直接比 "token 数" 没有意义；要比成本，只能比较"**同样长度的输出**要花多少钱"，而不是比 token 绝对值。这一点在写评测报告时特别容易踩。

## 四、观察 C（今天的重点）：三家全错，而且错得一样

三家的回答：

- zhipu：幻觉是大脑在没有相应外部刺激的情况下，产生的虚假感觉或知觉。
- siliconflow：幻觉是指在没有任何外部刺激的情况下，大脑产生的虚假感知。
- qwen：幻觉是指在没有相应外界刺激的情况下，个体主观上感知到真实存在的感觉体验（如看到、听到、闻到…）

**三家给的都是精神科/生理学的"幻觉"，没有一个提到大模型的 hallucination（编造事实、伪造引用）。**

### 这里的判断顺序很关键

看到"三家都错"，第一反应容易是"国内模型语义能力不行"。但**多家同向失败，先怀疑用例，不是先怀疑模型**。

验证方式：**同一家 provider，只改用例，不动模型**。

```
uv run eval-lab compare --prompt "在大语言模型（LLM）的语境下，用一句话解释什么是「幻觉」（hallucination）" --providers zhipu --repeat 1
```

结果：zhipu 给出"模型生成的文本内容与事实不符，即模型错误地创造…"——**答对了**。

同一个模型、同一个温度、同一段代码，改 prompt 就对了。**所以这次的失败不是模型能力问题，是我的测试用例缺语境**：只写"幻觉"，在中文里默认指向医学含义，模型答医学定义是"合理"的。

### 这就是"归因表"的用处

| 现象 | 先查什么 | 怎么确认 |
|---|---|---|
| 单家错 | 这条用例本身 | 同家换 prompt 重跑 |
| **多家同向错** | **用例/prompt 规格** | 补语境后同家是否答对 |
| 多家错得各不相同 | 真·模型差异 | 逐条看错在哪一层（格式/事实/指令） |
| 格式层全绿但内容错 | 评分口径 | 需要 rubric / judge，断言抓不到 |

顺序错了，就会把"我的用例写得含糊"记成"模型不行"，然后在简历/面试里讲成模型问题——一追问就露。
